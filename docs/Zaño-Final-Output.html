NSync

A Gamified Personal Knowledge and Review App

Brief Description of the Mobile Application

NSync is a gamified personal knowledge and memory application built with Kotlin and Jetpack Compose. It helps users capture important ideas, organize them into a knowledge base, create review cards, complete quiz-style review sessions, and track learning progress through XP, levels, streaks, accuracy, and mastery.

The first version of NSync was a mostly static prototype focused on matching the Figma interface. The current version connects the Android app to a Django REST Framework backend with PostgreSQL, JWT authentication, user-specific notes, flashcards, review sessions, profile data, progress tracking, and local settings.

0013      fun schedule(context: Context) {
0014          val preferences = SettingsPreferences.from(context)
0015          if (!preferences.getBoolean(SettingsPreferences.NOTIFICATIONS_ENABLED, true)) {
0016              cancel(context)
0017              return
0018          }
0019

0022          ).timeInMillis
0023          val alarmManager = context.getSystemService(AlarmManager::class.java)

0026              triggerAtMillis,
0027              pendingIntent(context)

0029      }
0030

0032          context.getSystemService(AlarmManager::class.java).cancel(pendingIntent(context))
0033      }
0034  
0035      private fun reminderCalendar(reminderTime: String): Calendar {
0036          val (hour, minute) = when (reminderTime) {
0037              "12:00 PM" -> 12 to 0
0038              "6:00 PM" -> 18 to 0
0039              else -> 8 to 0
0040          }
0041          return Calendar.getInstance().apply {
0042              set(Calendar.HOUR_OF_DAY, hour)
0043              set(Calendar.MINUTE, minute)
0044              set(Calendar.SECOND, 0)
0045              set(Calendar.MILLISECOND, 0)
0046              if (timeInMillis <= System.currentTimeMillis()) {
0047                  add(Calendar.DAY_OF_YEAR, 1)
0048              }
0049          }
0050      }

API Walkthrough

The backend exposes REST endpoints under /api/. Authentication uses JWT access and refresh tokens. Manual testing is documented in backend/tests.http, and DRF browsable API pages can be opened in a browser while the backend server is running.

  1. Run PostgreSQL with Docker Compose using the backend docker-compose file.
  2. Run Django migrations so the database has the latest tables.
  3. Start the Django server with python manage.py runserver 0.0.0.0:8000.
  4. Use POST /api/auth/register/ to create an account.
  5. Use POST /api/auth/login/ to receive access and refresh tokens.
  6. Use Authorization: Bearer <access_token> for protected requests.
  7. Use /api/notes/ to create and list user-owned notes.
  8. Use /api/flashcards/ to create and list flashcards connected to notes.
  9. Use /api/review/complete/ to submit review answers and update XP, streaks, accuracy, and mastery.
  10. Use /api/progress/ and /api/auth/me/ to verify the current user and learning progress.

Final Course Learning Reflection

While developing NSync, I learned how to build a complete Android application using Kotlin and Jetpack Compose. I learned how Compose apps are built from reusable composable functions and how each function can represent a specific part of the interface, such as cards, buttons, text fields, navigation bars, and progress indicators.

I learned how navigation works in Jetpack Compose using Navigation Compose. Routes, route arguments, callbacks, and NavHost helped connect screens together without putting all navigation logic inside every screen. I also learned how Scaffold helps create a consistent app layout, especially when using bottom navigation.

Another important lesson was organizing code by responsibility. The app started as a static prototype, but the code became easier to manage after separating screens, components, state classes, ViewModels, repositories, DTOs, and theme files.

I learned how to connect a mobile app to a backend using Retrofit and Django REST Framework. The Android app sends requests to the backend, receives JSON responses, and updates UI state through ViewModels. I also learned how JWT access and refresh tokens work, and how an interceptor attaches tokens to protected API requests.

On the backend side, I learned how Django models, serializers, API views, routes, and tests work together. I also learned the importance of user ownership so that notes, flashcards, quiz attempts, and progress records belong only to the signed-in user.

Overall, this project helped me understand how a prototype can grow into a full-stack mobile application with real data, authentication, organized code, and documentation.
